# JAKAL Core v3 — production persistence & service layer

A clean-room rebuild of the JAKAL backend's data + service tier, addressing the
P0/P1 findings from the architecture teardown. Async SQLAlchemy 2.0, real
hybrid post-quantum signing, a genuine identity/RBAC gate, and an isolated,
**passing** test suite.

> Scope note: this is the reference implementation for the highest-value
> modules (identity, crypto/PQC, approval gate, Ares rollup, Canvas, quantum
> queue). Every other module in the platform follows the exact same pattern —
> typed model → service (no FastAPI import) → async session dependency →
> isolated tests. This package is the pattern proven end-to-end, not a claim
> that all 32 tables are re-implemented here.

## What this fixes (mapped to the teardown)

| Finding | Fix in this package |
|--------|---------------------|
| **GAP-01** no auth | `auth.py` — JWT bearer verify → `Principal`; RBAC ranks; `operator_id` never from the body. Approval gate enforces **separation of duties**. |
| **GAP-02** DuckDB single-writer, 15 connections | `db.py` — one async engine + pooled `async_sessionmaker`; `get_session()` request dependency. Runs on Postgres (prod) and SQLite (tests), same ORM. |
| **GAP-03** PK collision, non-isolated tests | UUID/identity PKs (no shared sequence); one fresh DB **per test** (`conftest.py`). |
| **GAP-04** boot crash on default config | `config.py` — optional integrations disabled by default; secrets required only in `prod`. |
| **GAP-05** silent Ed25519 downgrade | `crypto/pqc.py` — hybrid ML-DSA-65 **+** Ed25519; `strict` mode makes PQC mandatory; algorithm recorded per signature. |
| **GAP-07** ephemeral keys | `crypto/envelope.py` — data keys stored only KEK-wrapped; `crypto_service` wires the previously-dead key-registration path. |

## Layout

```
jakal_core/
  config.py            typed settings, fail-fast prod secrets
  logging_config.py    structured JSON logging + correlation id
  db.py                async engine, sessionmaker, get_session dependency
  models.py            SQLAlchemy 2.0 typed models (13 domain tables)
  auth.py              JWT verify, Principal, RBAC, separation-of-duties helper
  errors.py            domain exception hierarchy (maps to HTTP in API layer)
  crypto/
    pqc.py             HybridSigner: ML-DSA-65 + Ed25519
    envelope.py        AES-256-GCM envelope key wrapping
  security/
    sanitize.py        target allowlist + sandbox argv/interpreter guard
  services/
    crypto_service.py    audit signing + key lifecycle (/api/crypto)
    approval_service.py  human gate + RBAC + SoD (/api/approval)
    ares_service.py      derived global-matrix rollup + event bus (/api/ares)
    canvas_service.py    patch pipeline + rollback (/api/canvas)
    quantum_service.py   bounded job queue + drainer (/api/quantum, /api/qaip)
alembic/               async migration env + autogenerated initial revision
tests/                 40 real tests (Phase 1 unit/integration + Phase 2 stress)
```

## Run it

```bash
pip install "sqlalchemy[asyncio]>=2.0" aiosqlite asyncpg alembic \
            "pydantic-settings>=2" pyjwt dilithium-py cryptography \
            pytest pytest-asyncio

# tests (isolated SQLite per test)
python -m pytest                      # -> 53 passed

# apply the schema migration (SQLite check DB, or point at Postgres)
JAKAL_MASTER_KEY=… JAKAL_JWT_SECRET=… python -m alembic upgrade head
```

For Postgres, set `JAKAL_DATABASE_URL=postgresql+asyncpg://user:pass@host/db`
and `sqlalchemy.url` in `alembic.ini` to the same. No model changes required.

## Test coverage (real, executed)

**Phase 1 — unit & integration (20):** PQC backend is real ML-DSA-65; sign→verify
roundtrip; tamper detection; strict-mode PQC requirement; key register/unwrap/
rotate/revoke/list lifecycle; approval staging + RBAC + separation of duties;
execution gating; Ares uninitialised + blocked-threat rollup; JWT decode/expiry/
tamper.

**Phase 2 — stress, threat & failure (20):** injection fuzzing of targets and
sandbox commands (incl. shell-interpreter denylist); **50- and 100-way
concurrent inserts proving the GAP-03 PK collision is gone**; double-decide /
double-execute conflict handling; 25-job quantum queue drain with bounded
concurrency; patch blocked-until-approved + rollback; AES-GCM envelope tamper
detection; **JWT `alg=none` confusion and wrong-key forgery rejected**.

The two failures found on first run (a fixture event-loop binding bug and a
missing shell-interpreter denylist) were fixed in the implementation — see the
git-style notes in `conftest.py` and `security/sanitize.py`.

## Not done here (honest boundaries)

* The FastAPI routing layer (dependency wiring of `get_session` + `require_role`)
  is specified but not included — the services are deliberately framework-free.
* Fabric/Horizon/EDR service bodies follow the same pattern and are not all
  filled in; their models are present.
* PQC private keys are process-generated for demonstration; production loads
  them from KMS/HSM behind the same `HybridSigner` interface.
