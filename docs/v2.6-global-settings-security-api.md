# JAKAL v2.6 — Global Settings & Security API Reference

This document covers every endpoint added in v2.6 to back the **Global
Settings & Security** tab (Profile, Login Encryption, API Integration,
EAS R&D, Trade Secrets, Penetration Testing, RBAC, Auditing, Key
Management) plus the previously-unbacked Human Layer Security and
GACyber Toolkit pages (Dark Web Monitoring, Awareness Training, Phishing
Campaigns, CheatSheet Library).

All endpoints are mounted under `/api` (see `backend/app.py`). Interactive
docs are always available live at `/docs` (Swagger UI) once the backend is
running — this file is the narrative companion, not a replacement for it.

## Authentication model

See `backend/dependencies.py` for the full rationale. Short version:

- A fresh install has **zero users** and every permission-gated endpoint
  is open (still logged to `audit_log`, actor recorded as `anonymous(bootstrap)`).
- The **first** account created via `POST /iam/auth/register` automatically
  becomes `root_admin`. Every account after that gets `read_only` until an
  admin grants it a better role.
- From that point on, permission-gated endpoints require
  `Authorization: Bearer <jwt>` (obtained from `POST /iam/auth/login`) and
  the caller's role must carry the specific `permission_key` the route
  declares.
- Force enforcement even with zero users via `JAKAL_REQUIRE_AUTH=true`.

## `/api/iam/*` — Identity & Access Management

| Method | Path | Auth | Purpose |
|---|---|---|---|
| POST | `/iam/auth/register` | open | Create an account. First ever = root_admin. |
| POST | `/iam/auth/login` | open | Password (+TOTP if MFA on) → JWT. Account locks after 5 bad attempts (15 min). |
| POST | `/iam/auth/logout` | bearer | Revoke the current session. |
| GET | `/iam/auth/me` | bearer | Profile: roles, permissions, timestamps. |
| POST | `/iam/auth/change-password` | bearer | Requires current password. |
| POST | `/iam/auth/mfa/enroll` | bearer | Returns a TOTP secret + `otpauth://` URI for a QR code. |
| POST | `/iam/auth/mfa/confirm` | bearer | Verifies the first code, turns MFA on. |
| POST | `/iam/auth/mfa/disable` | bearer | Turns MFA back off. |
| GET | `/iam/rbac/roles` | open | Roles + their permissions + assigned-user counts. |
| GET | `/iam/rbac/permissions` | open | The full permission catalog. |
| POST | `/iam/rbac/roles` | `iam:manage_roles` | Create a custom role. |
| POST | `/iam/rbac/roles/{role_key}/permissions` | `iam:manage_roles` | Grant a permission to a role. |
| DELETE | `/iam/rbac/roles/{role_key}/permissions/{permission_key}` | `iam:manage_roles` | Revoke it. |
| GET | `/iam/rbac/users` | open | Users + their assigned roles. |
| POST | `/iam/rbac/users/{user_id}/roles` | `iam:manage_users` | Assign a role. |
| DELETE | `/iam/rbac/users/{user_id}/roles/{role_key}` | `iam:manage_users` | Unassign it. |
| POST | `/iam/api-keys` | `iam:manage_keys` | Issue a key. **Secret shown once** — only its SHA3-256 hash is stored. |
| GET | `/iam/api-keys` | bearer | List my keys (metadata only). |
| POST | `/iam/api-keys/{key_id}/revoke` | `iam:manage_keys` | Revoke. |
| GET | `/iam/audit/log` | `audit:read` | Structured audit trail (filter by actor/action). |
| GET | `/iam/audit/export` | `audit:read` | Same, as a Markdown table. |

Seeded roles (`routers/iam.py::_DEFAULT_ROLES`): `root_admin` (`system:*`),
`security_analyst` (day-to-day operational permissions), `read_only`
(`read:dashboard`, `audit:read`) — these are the same three roles the
frontend's RBAC tab used to hardcode as a static table; they're real rows
now.

## `/api/vault/*` — EAS R&D + Trade Secrets

| Method | Path | Auth | Purpose |
|---|---|---|---|
| POST | `/vault/eas-rd/scan` | bearer | **Live** OSV.dev dependency scan of every pinned package in `backend/requirements.txt` and `backend-v3/requirements.txt`. Replaces the old `setTimeout()`-simulated "AI scanning" theater. |
| GET | `/vault/eas-rd/last-scan` | open | Cached result of the most recent scan. |
| POST | `/vault/items` | `vault:write` | Create an item — AES-256-GCM encrypted at rest via `crypto/encryption_manager.py` before it touches DuckDB. |
| GET | `/vault/items` | `vault:read` | List metadata only (title, classification, owner) — **never** ciphertext or plaintext. |
| GET | `/vault/items/{item_id}` | `vault:read` + role membership in `allowed_roles` (or ownership) | Decrypt and return one item, with a SHA3-256 integrity check. |
| DELETE | `/vault/items/{item_id}` | `vault:write` | Soft-delete (archive). |

## `/api/darkweb/*` — Dark Web Monitoring

| Method | Path | Auth | Purpose |
|---|---|---|---|
| POST | `/darkweb/watchlist` | `darkweb:manage` | Add an email/domain to monitor. |
| GET | `/darkweb/watchlist` | open | List the watchlist. |
| POST | `/darkweb/scan` | `darkweb:manage` | Checks every watched email against **Have I Been Pwned** (real breach corpus). Requires `HIBP_API_KEY` (HIBP's own anti-abuse requirement — see haveibeenpwned.com/API/Key); without it, returns a clear "connector not configured" result instead of fabricating findings. |
| GET | `/darkweb/findings` | open | List findings. |
| POST | `/darkweb/findings/manual` | `darkweb:manage` | Record a finding from a paid feed (Recorded Future, SpyCloud, Flashpoint, etc.) this deployment has separately contracted — same table, analyst-entered. |
| POST | `/darkweb/findings/{finding_id}/acknowledge` | `darkweb:manage` | Mark reviewed. |

| Method | Path | Auth | Purpose |
|---|---|---|---|
| GET | `/awareness/training/modules` | open | Seeded curriculum (phishing, password hygiene, social engineering, data handling, incident reporting, MFA/device hygiene). |
| POST | `/awareness/training/modules/{module_key}/complete` | bearer | Record a score; ≥80 passes. |

| Method | Path | Purpose |
|---|---|---|

| GET | `/cheatsheet/categories` | Category list. |
| GET | `/cheatsheet/search` | Filter by phase/category/keyword. |
| GET | `/cheatsheet/entries/{entry_id}` | Full entry content. |
| GET | `/cheatsheet/graph` | Ontology graph (objects + links) for a visual explorer. |

## Environment variables introduced

| Variable | Purpose | Default |
|---|---|---|
| `JAKAL_REQUIRE_AUTH` | Force auth enforcement even with zero users | `false` |
| `JAKAL_JWT_TTL_MINUTES` | Session token lifetime | `60` |
| `HIBP_API_KEY` | Enables live Dark Web Monitoring breach checks | unset (connector reports "not configured") |

`JAKAL_MASTER_KEY` (already existed) is reused to derive the JWT signing
secret — see `dependencies.py::_jwt_secret()`.
