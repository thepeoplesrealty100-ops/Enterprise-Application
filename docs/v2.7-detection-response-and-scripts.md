# JAKAL v2.7 — Detection & Response, Script Library, Purpose-Built Widgets

Everything in this pass builds on the safety architecture v2.6 documented
(`docs/v2.6-global-settings-security-api.md`) rather than adding a second
one: nothing here executes real commands against a live target on its
own. It reuses the platform's existing authorization gate
(`tools/authorization.py`), Human Approval Gate (`approval_requests`
table / `security_agents/exploit_agent.py`'s staging pattern), and the
one real subprocess-execution path in the whole codebase — the sandboxed
`VMOrchestrator` (Docker containers the operator provisions, never the
host, never a live target).

## Grounding

- **NIST SP 800-61 Revision 3** (finalized April 2025) retired the old
  four-phase incident-response lifecycle in favor of mapping IR onto
  **NIST CSF 2.0**'s six functions — IR itself covers Detect/Respond/
  Recover. [Linford & Co. summary](https://linfordco.com/blog/nist-sp-800-61/), [Tandem summary](https://tandem.app/blog/updated-nist-incident-response-guidance-sp-800-61-rev-3)
- **MITRE D3FEND** (d3fend.mitre.org) is the NSA-funded defensive-technique
  counterpart to ATT&CK — 245+ techniques including Content Quarantine
  (D3-CQ), Network Isolation, and Execution Isolation under its Isolate
  tactic. [D3FEND Matrix](https://d3fend.mitre.org/), [Content Quarantine — D3-CQ](https://d3fend.mitre.org/technique/d3f:ContentQuarantine/), [Vectra overview](https://www.vectra.ai/topics/mitre-d3fend)
- **NIST IR 8547** (Nov 2024 initial public draft) sets the post-quantum
  migration timeline this platform's `pqc_crypto_agility_incident`
  playbook cites: RSA-2048/ECC P-256-class algorithms deprecated by 2030,
  disallowed by 2035; CNSA 2.0 requires PQC support in new National
  Security Systems acquisitions from January 2027. [Entrust: NIST's Urgent Call](https://www.entrust.com/blog/2024/12/nists-urgent-call-deprecating-traditional-crypto-by-2030), [Entrust: CNSA 2.0](https://www.entrust.com/resources/learn/what-is-cnsa-2-0)
- **Open-source SOAR architecture** (TheHive+Cortex+MISP+Shuffle pattern)
  informed the case/enrichment/playbook-execution split here:
  `threat_intel` table = IOC store (MISP-like), `EdrMdrEngine` = case/
  playbook execution, `routers/response.py` = the orchestration/
  enrichment layer. [UTMStack: Top 5 Open Source SOAR](https://medium.com/@marketing_38143/top-5-open-source-soar-solutions-in-2025-f7e931546dd0), [rokibulroni: Open OSC stack](https://rokibulroni.com/solutions/open-source-soc-stack-thehive-cortex-shuffle/)

## New: real script catalog (`payloads/script_catalog.py`)

43 real `.py`/`.sh`/`.pl`/`.rb` scripts already sat in `gacyber_toolkit/`'s
phase folders (01-Reconnaissance through 07-Post-Exploitation) with zero
API surface. `ScriptCatalog` walks those folders at process start,
classifies each by an explainable keyword-based risk heuristic (matching
`threat_scoring.py`'s philosophy — inspectable, not opaque), and exposes
them read-only plus a staged-execution path:

1. `GET /api/cheatsheet/scripts` — browse (filter by phase/risk/language).
2. `POST /api/cheatsheet/scripts/{id}/stage` — authorization-gated
   (`check_authorization_and_scope`), creates an `approval_requests` row.
   **Never executes anything itself.**
3. A human approves at the existing `POST /api/approval/{id}/approve`.
4. `POST /api/cheatsheet/scripts/{id}/run-in-sandbox` — only once approved,
   and only inside a sandbox container the operator already created via
   `POST /api/vm/sandboxes`. Content is base64-transported into the
   container (no shell-quoting injection surface) and the approval's
   recorded `content_sha256` is re-checked against the live script file
   before running, so a script edited after staging can't be silently
   substituted.

## New: Detection & Response (`routers/response.py`)

| Action | Real & immediate, or staged? | Why |
|---|---|---|
| `POST /response/ioc/block` | Immediate | Adding a deny-list entry can't cause harm — pure defense |
| `POST /response/quarantine` (artifact) | Immediate | Data-layer flag, reversible |
| `POST /response/quarantine` (host) | **Staged** | Claims to touch infrastructure this platform doesn't own |
| `POST /response/isolate-host` | **Always staged** | Same — see `security_agents/vm_orchestrator.py`'s own scope note |
| `POST /response/triage` | Scores + recommends; auto-stages containment only above threshold | Mirrors Ares's existing severity-threshold HITL pattern |

`triage` reuses the existing, deterministic `threat_scoring.score_recon_finding`
(no new scoring model — one already existed and was under-used) and
recommends from the **real, existing** playbook catalog via keyword/category
match — it never invents a response procedure.

## New: 8 playbooks (`security_agents/edr_mdr.py`)

Added to the existing 6 (suspicious login, phishing quarantine, ransomware,
data exfiltration, privileged account compromise, anomalous process
execution): **supply chain compromise** (ties to the v2.6 EAS R&D OSV.dev
scanner), **cloud account compromise**, **DDoS response**, **insider
threat data staging**, **IoT/OT device compromise**, **emergency
vulnerability patch** (ties to EAS R&D + pentest findings), **wireless
rogue AP/evil twin** (ties to the existing wireless module), and
**PQC crypto-agility incident** (the quantum tie-in — grounded in the real
NIST IR 8547 timeline above, not speculative "AI vs. quantum" framing).
Every step is tagged `csf2_function` (CSF 2.0 Detect/Respond/Recover);
steps with a real defensive-technique mapping also carry `d3fend_technique`.

## New: MFA QR code

`POST /api/iam/auth/mfa/enroll` now returns `qr_data_uri` — a server-
rendered SVG QR code (via `segno`, pure Python, no PIL/native
dependency) as a base64 `data:` URI, so any TOTP authenticator app can
scan it directly instead of requiring the operator to type a 32-character
base32 secret by hand. The frontend's Login Encryption / Profile panel
now runs the full enroll → scan → confirm flow.

## New DB tables (schema v2.7)

`remediation_actions` — outcome ledger for every Detection & Response
action, cross-linked to `approval_requests` (staged actions) and
`unified_security_events` (every action also emits an Ares rollup event,
so Predictive Command reflects response activity, not just offense).

## Repository cleanup

`gacyber_toolkit/CheatSheets/` had a flat, whitespace-only-different mirror
of all 42 runnable scripts that also live under the phase folders
(`01-Reconnaissance/` through `07-Post-Exploitation/`) — verified
byte-for-byte after stripping line endings, not assumed. Nothing in the
codebase read scripts from that flat copy (only `cheatsheet_data.json`,
the `.docx`/`.pdf` source documents, and the `pdf_extracts`/reference
`.txt` files in that folder are actually used, by `cheatsheet_ontology.py`),
so the 42 duplicate `.py`/`.sh`/`.pl`/`.rb` files were removed. The
phase-folder copies are the ones `payloads/script_catalog.py` indexes —
this was already true before the cleanup (it dedupes by filename and
prefers the phase-folder path), so removing the flat mirror changes
nothing functionally; confirmed via `ScriptCatalog().stats()` reporting
the same 43-script count before and after, and the full test suite
passing unchanged (96/96, five consecutive runs).

## Honest limitations

- Host isolation/quarantine are staged, audited, D3FEND-tagged
  authorization *records* — this platform has no live EDR/firewall agent
  on a customer's actual network to enforce them. The extension point is
  documented in `routers/response.py`'s module docstring: point a real
  EDR's webhook at an approved `remediation_actions` row.
- Script risk classification is a static keyword heuristic, not a
  sandboxed static-analysis pass — treat `risk_level` as a triage hint,
  not a guarantee.
- The purpose-built widgets read real data but several (Energy Core,
  Automation Controls) still don't have *write* controls in the UI (e.g.
  an actual throttle slider that POSTs a new limit) — the backing
  endpoints for that would need to be added to `routers/qaip.py` /
  `resonance.py` first; out of scope for this pass, which focused on
  turning existing read endpoints into real widgets.
