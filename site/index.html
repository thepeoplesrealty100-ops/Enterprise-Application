JAKAL

A security operations platform you run yourself — penetration-testing pipeline, human approval gates on anything that touches a real machine, and a post-quantum-signed audit trail behind all of it.

View on GitHub Deployment guide README

This page is documentation, not a running instance. JAKAL is a FastAPI backend with an embedded DuckDB database, so it can't run on static hosting like GitHub Pages — there's no live demo here. Start it on your own machine with the one command below and the dashboard comes up at localhost:8000.

Run it

Docker is the path that's actually exercised by the repo's own tooling.

# from the repo root
docker compose up -d --build

Then open http://localhost:8000 for the operator dashboard, or http://localhost:8000/docs for the auto-generated API reference. Want it pre-populated with a realistic sample engagement to click through? Run python3 seed_demo_data.py from backend/ first.

What's in it

The parts that are built and tested, not the roadmap.

Pentest pipeline

Recon → enumeration → web → report, staged through real security agents rather than canned output.

Human approval gates

Nothing that reaches out and touches a machine it doesn't own runs on its own. Isolation and quarantine are staged as approval requests a person decides on.

Post-quantum audit trail

ML-DSA-65 (Dilithium3) signs agent actions and audit entries, so the log is non-repudiable.

Identity & access

Bcrypt password hashing, TOTP multi-factor, role-based permissions, and an audit log on sensitive endpoints.

Ontology engine

A graph of assets and findings that supports attack-path and blast-radius queries across related hosts.

Quantum engine

Real Qiskit circuits on the local Aer simulator, or routed to IBM hardware if you supply a token.

How it's put together

Deliberately boring where it counts: one process, one file for the database.

BackendFastAPI (Python 3.11), 45 routers mounted on one app
DatabaseDuckDB, embedded — a single file on disk, no external database to run
DashboardPlain HTML and vanilla JavaScript, served by the backend. No build step, no bundler
DeploymentDocker Compose. Kubernetes manifests are included but not cluster-tested
LLMOllama by default, or Claude if you set an API key. Optional either way

Getting oriented

A reasonable first half-hour.

  1. Bring it up and seed the demo data

    Gives you a sample engagement with scope, findings, MITRE mappings and a pending approval request already in place.

  2. Open the dashboard at localhost:8000

    Global Dashboard shows fleet posture and recent agent activity pulled from the live database.

  3. Walk an approval through the gate

    Find the pending request, approve it, and watch the signed decision land in the audit trail. This is the core safety loop.

  4. Browse /docs

    Swagger UI generated from the routes that are actually mounted — the honest API surface, not a written list that can drift.
